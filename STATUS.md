- Hata enjeksiyonu: gerçek Redis Lua tamamlandıktan sonra yanıt kaybı PostgreSQL'e hak/kayıt yazmadı; Redis=`1` kaldı. Constraint kaldırılınca aynı kimlik Redis ön sonucuyla tek günlük hak ayırdı. Sonraki günlük ret Redis'in ikinci kapasitesini tüketti; hız reddi yeni kapasite tüketmedi.
- HTTP entegrasyonunda commit sonrası yanıt yazımı kaybı ve ardından Redis hata enjeksiyonu sırasında aynı kimlik kayıtlı sonucu döndürdü; Redis çağrılmadı. Yeni karar `503` verdi ve günlük kullanım artmadı. İzin/günlük ret/hız ret tekrarları politika güncellemesinden sonra ilk limit/sürüm/sonucu korudu; yeni karar güncel sürümü kullandı. Kalıcı ve tamamlanmamış Redis ön sonucunda farklı işlem aynı kimlikle `409`; eksik politika `403`, yanlış anahtar `401` oldu.
- `compose.qg06.yaml`, temel ve QG-05 topolojisi üzerine ayrı `quotagate-qg06` proje/hacminde iki birleşik API kopyası ve örnek API çalıştırdı. `pwsh -NoProfile -File ./scripts/smoke-qg06.ps1` geçti: 60 benzersiz karar `3/4/53`; 20 tekrar tek hak; PostgreSQL kayıt hatası `503` ve korunmuş Redis kapasitesi; aynı kimlikle tamamlanma; politika değişiminden sonra ilk sonucun tekrarı. Salt okunur, sır içermeyen kaynak/modül kopyaları kullanıldı; race PostgreSQL'i dış port açmadan, gerçek parola veya kalıcı hacim olmadan yalnızca test verisi tuttu.

## Açık sınır ve ortam

- QG-06 `serve-combined` modunda `/v1/decisions` ve örnek `/jobs` birleşik hız/günlük kararını kullanıyor. Redis ve PostgreSQL arasında ortak transaction yok: Redis ön kapasitesi günlük ret/DB arızasında geri verilmez; PostgreSQL günlük hak yalnızca nihai izin commit olduğunda ayrılır. Belirsiz commit veya yanıt kaybında aynı kimlikle tekrar kalıcı sonucu açığa çıkarır. Redis veri kaybından sonra tamamlanmamış ön sonucun devamlılığı garanti edilmez. Politika değişimiyle araya giren tamamlanmamış Redis ön sonucu eski hız limitini koruyabilir; nihai kararın günlük limit/sürümü güncel PostgreSQL politikasındandır. Kalıcı karar tekrarı ilk sonucu korur.
- Müşteri kararları Redis çağrısı boyunca PostgreSQL kilidi ve bağlantısı tutarak sıralanıyor; bu tercih müşteri başına eşzamanlılığı sınırlar. Performans/üretim kapasitesi ölçülmedi. QuotaGate günlük kotayı **izin verilmiş karar** olarak sayıyor, handler başarısını bilmiyor. İstemcide otomatik taşıma tekrarı henüz yok; ayrı inbound tekrar yeni hak talebidir. Sınırlı aynı-karar tekrarı QG-07'de eklenecek. İki bağımlılığın kesinti/toparlanma demosu ve v0.2 bitişi QG-08'de.
- Örnek iş ve `GET /demo/stats` sayacı yalnızca yerel, süreç içi kanıttır; yeniden başlatmada sıfırlanır. Örnek `/health/live` QuotaGate readiness durumunu göstermez. Kalıcı müşteri kullanımı PostgreSQL'den alınır.
- Test Compose konteynerleri kabulden sonra `down` ile kapatıldı; izole `quotagate-qg01_pgdata` hacmi korundu. `.env.compose` Git dışında. Windows'ta CGO kapalı olduğu için race testi Linux Go konteynerinde çalıştırıldı. QG-04'te otomatik onay denetimi DB parolasının Go konteynerine aktarılmasını reddetti; sır paylaşmadan ayrı yerel PostgreSQL ve kapalı ağlı race koşuları tamamlandı.
- QG-05 ayrı Compose proje/hacmini kullandı; test müşterileri ve Redis anahtarları temizlendi. PostgreSQL müşteri/sayaç/karar sayıları `0|0|0`, Redis demo DB `0` ve test DB `15` anahtar sayıları `0/0` doğrulandı. QG-05 konteynerleri `down` ile kapatıldı; `quotagate-qg05_pgdata` ve önceki `quotagate-qg01_pgdata` korundu.
